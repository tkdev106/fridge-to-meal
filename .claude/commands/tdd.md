# /tdd — テスト駆動で1件実装する

引数で指定された対象を**テストから**作る。方針の正は `docs/testing.md`。

```
test-designer（洗い出し） → test-writer（赤） → implementer（緑） → design-reviewer
```

**この命令はブランチも PR も作らない。** 1周ぶんの実装の中身だけを担う。
ループ（枝を切る・PR・マージ）は `/next` の仕事であり、`/next` は実装の段でこれを呼ぶ。

引数が無いときは、いま何を実装しようとしているのかを聞き返す。**推測で始めない。**

## サブエージェントに渡すもの

**3つとも前の文脈を持たずに始まる。** 会話を見ていない相手に渡す前提で、毎回そろえる。

| 渡す先 | 渡すもの |
| --- | --- |
| `test-designer` | 対象のタスク（backlog の ID か、実装したい振る舞いの文）/ コンテキスト（`meal` `pantry` `catalog` `identity`）と層 / 関係する FR・C-n・ADR の番号 |
| `test-writer` | **検分後の**テストケース一覧（表のまま）/ 対象のファイルパス / 既存の似たテストのパス |
| `implementer` | 赤いテストのパスとその落ち方 / 置かれたスタブ / 対象コンテキストと層 |
| `design-reviewer` | `git diff origin/main...HEAD`（差分そのものではなく、見る対象として） |

## 手順

1. **対象を確かめる。** `docs/backlog.md` に無いものは着手しない（`CLAUDE.md`）。
   1周で2件やらない。**1周 = 1つの振る舞いのかたまり**
2. **設計文書を自分でも読む** — `docs/domain-model.md` の該当集約と第7章、関連 ADR。
   サブエージェントの報告を検分するには、こちらが根拠を持っている必要がある
3. **`test-designer` を呼ぶ。**
4. **一覧を検分する。ここが人の代わりに判断する唯一の場所。**
   - 根拠（C-n / FR-n / 不変条件）の無い行を**落とす**
   - 実装詳細を握っている行（呼び出し回数・内部状態）を**落とす**（`docs/testing.md` 第3章）
   - **世帯の分離（C-9）の行があるか**を確かめる。リポジトリを触るなら必須
   - 「判断が要るもの」に行があれば、**そこで止まる**（下記）
5. **`test-writer` を呼ぶ。** 渡すのは**検分後の一覧**
6. **赤を自分で確かめる。** 報告を信じず `pnpm test <パス>` を走らせ、
   **落ち方が `未実装` か期待値の不一致であること**を見る。
   `Cannot find module` や型エラーで落ちているなら赤ではない — `test-writer` に差し戻す
7. **`implementer` を呼ぶ。**
8. **緑を自分で確かめる。** `pnpm verify` を走らせる（`/verify`）。
   `git status --porcelain -- '*.test.ts' 'apps/api/test'` が**空**であることも見る —
   **テストが書き換わっていたら、緑は意味を持たない**
9. **`design-reviewer` を呼ぶ**（`git fetch origin main` の後）。指摘は直すか、直さない理由を残す
10. **コミットする。** テストと実装を**同じコミットに入れる** — 片方だけの状態は `main` で緑にならない。
    メッセージは `git diff --staged` から書く（`.gitmessage` が形式）

## 差し戻す条件

**次の段に進めず、前の段に戻す。**

| 見たもの | 戻す先 |
| --- | --- |
| 根拠の無いケース、実装詳細のケースが多い | `test-designer`（落とす理由を添えて） |
| 赤が「モジュールが無い」「型が合わない」 | `test-writer`（スタブが足りない） |
| `toThrow()` が引数なし、`vi.fn()` の呼び出し検証がある | `test-writer`（`docs/testing.md` 第2章・第6章） |
| テストファイルが書き換わっている | `implementer`（テストを戻してから再実行） |
| 実装が入力を見て期待値を返しているだけ | `implementer`（ケースを1件足すのではなく、実装を直させる） |

## 止まる条件

以下に当たったら**進めずに止まる。** そこまでの成果は push し、
「何が決まれば進むか」を**1つの質問**にまとめて終える。黙って止まらない。黙って進めない。

- テストケースの洗い出しで、確定事項 C-1〜C-16 を破る必要が出た
- 未決事項の決定が必要になった（LLM プロバイダ / 食材マスタ / 献立の保持期間 / 期限の区別）
- `docs/requirements.md` の FR / NFR に無い機能が必要になった
- 依存パッケージの追加が必要になった
- 同じ検証失敗を2回直せなかった
- **`implementer` が「テストが仕様として誤っている」と報告した** —
  テストを直すかどうかは仕様の判断であり、実装の判断ではない

## 報告

```markdown
## TDD 1周: <対象>

| 段 | 結果 |
| --- | --- |
| 洗い出し | N 件（うち検分で落とした N 件） |
| 赤 | N 件が `未実装` / 期待値の不一致で落ちた |
| 緑 | `pnpm verify` ✅ / ❌ |
| 設計レビュー | 違反なし / N 件（対応: …） |

### 落としたケース
### 残した判断・止まった点
```
