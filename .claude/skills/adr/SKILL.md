# ADR を起こす

書き方の規則と本文の型の正は `docs/adr.md` 冒頭の「書き方」。ここには手順だけを置く。

1. **ADR にするものか確かめる。** 設計判断か。運用・事業・製品の範囲は書かない。調べて推す案は、ユーザーが選ぶまで ADR にせずスレッドの返信で答える
2. **番号を採る。** B章の決定一覧の最大の番号に1を足す（欠番も数える）
3. **本文を C章の末尾に書く。** 冒頭「書き方」の型に沿う。状態は `提案`（`承認` に変えるのはユーザーだけ）
4. **B章の決定一覧に1行足す。** 題と状態を本文の見出しと同じにする。冒頭の版の行の番号の範囲も改める
5. **置き換えるなら、** 冒頭の手順に沿って旧 ADR の状態を `置き換え済み` に改め、生きた参照を向け直す。旧 ADR の本文は書き換えない
6. **出す前に点検する。** 冒頭「書き方」の規則を1つずつ当てる。機械で拾える経緯は次で探す（引っかかったら規則4に沿って書き直す）

   ```sh
   # 新しい ADR の本文だけを対象にする（nnn は採った番号）
   awk '/^### ADR-nnn/{f=1;print;next} /^### ADR-/{f=0} f' docs/adr.md \
     | grep -nE '20[0-9]{2}-[0-9]{2}-[0-9]{2}|#[0-9]+|\bB-[0-9]+|ユーザーが|監査|L[0-9]+|行目'
   ```

7. **他の文書を追随させる。** `.dependency-cruiser.cjs` を変える決定なら A章の表と `CLAUDE.md` の表を、規則を変える決定なら該当する `docs/` を同じ PR で直す
