> 画面がどの状態を持ち、何がどこにあり、どこへ遷移するかの正は従来どおり `docs/screen-design.md`。

| ファイル | 中身 |
| --- | --- |
| `screens.html` | **原本。** 受け取ったバンドルをそのまま置いた（約16MB。書体と React を内包するため）。ブラウザで開くと画面の一覧が描かれる |
| `src/*.dc.html` | 原本から部品ごとに抜き出した HTML。**中身は原本と同じで、読むための写し**（grep と差分のため）。`index.dc.html` は一覧の頁で、書体の `@font-face` だけを除いてある |

抜き出しは原本の `<script type="__bundler/manifest">`（base64、`compressed` なら gzip）と
`__bundler/ext_resources`（部品の名前と uuid の対応）を読めばできる。仕組みを常設しない（ADR-053 結果5）。

## トークン

原本で使われている色はこれだけである。名前は実装の周（ADR-055 の `:root`）で付ける。

| 値 | 使われ方 |
| --- | --- |
| `#FAF9F6` | 地 |
| `#FFFFFF` | カード・入力欄・パネルの面 |
| `#ECE7DF` | 控えめな面（注意表示・案内の帯・「その他」の帯・設定の帯） |
| `#E3DED6` | 区切り線・枠 |
| `#8C877F` | 入力欄の枠・カードの hover の枠 |
| `#1F1E1B` | 文字・主の操作の地 |
| `#55524C` | 補助の文字・主の操作を押している間 |
| `#6E6A63` | さらに弱い文字（`任意`・置き文字・無効） |
| `#4A6236` / `#E2EBD0` | 緑の文字 / 緑の地（再利用の印・賄える・在庫が変わった） |
| `#A33A26` / `#F7E3DC` | 赤の文字 / 赤の地（今日まで・不足・削除） |
| `#8A5A12` / `#F5EBD8` | 黄土の文字 / 黄土の地（期限が近い） |

文字の大きさは 12 / 14 / 16 / 18 / 20 / 26px、太さは 400 / 500 の2つ。角は丸めない（`border-radius: 0`）。
操作の高さは 48px（副）と 56px（主）、押せる要素は 44px 以上。フォーカスは `outline: 2px solid #1F1E1B; outline-offset: 2px`。**操作と入力欄は `outline-offset: -2px` で枠に重ねて1本にする**。文字色・赤の地の操作は `#FAF9F6` の線を縁から 4px 内側に引く。

**PC（幅 1024px 以上）のタブの画面（献立・献立詳細・冷蔵庫・履歴・設定）は、どれも左右の余白 48px・余白の内側の最大幅 1080px で左に寄せる。**
主の操作（`作った`・保存・`食材を登録する`）は最大幅を持たず、置き場の横いっぱいに広げる（PC の献立タブの `新しい献立を見る` は左 360px に置き、右に案内を並べる）。
案内の文（0件・読み込み中など）は行と同じ左右 16px を取り、履歴の0件の案内は切り替えから 24px 離す。サイト名は `fridge to meal`（ブラウザの題・PWA の名前・ロゴ）。

## 了承が要るもの

デザインが今の振る舞い（`docs/screen-design.md` の決めたこと）と食い違う箇所。**見た目と文言ではなく振る舞いの変更なので、
実装の前にユーザーの了承を取る**（2026-09-29 のユーザー指定。プロジェクトの運用の指示「機能を追加する際は着手前に確認する」）。**2026-10-02、ユーザーが4つとも答えた**（「決定」の列）。

| # | デザイン | 今の決めごと | 決定（2026-10-02） |
| --- | --- | --- | --- |
| 1 | **在庫の削除に確認を挟む**（9b）。SP は横スワイプで行の下から `削除` が現れ、押すと下から確認の面が出る。PC は行末の `…` → `削除` → 中央のダイアログ。最初の焦点は `やめる` | 5章「削除は行のスワイプ。**確認は出さない**（登録し直すコストが低い）」 | 確認を挟む（B-69） |
| 2 | **PC の行末の操作**（`…` → `編集` / `削除`） | 5章「行の中に『編集』の操作を出さない」。ただしこれが入るとキーボードと読み上げからも編集・削除に届く（今は届かない） | 置く（B-69） |
| 3 | **オフラインの帯**（`オフラインです`） | FR-41（Must）だが、今のアプリにオフラインの検知も帯も無い | 実装する（B-70） |
| 4 | **ログインに `アカウントを作る` が無い** | 今はログインの画面からアカウントを作れる（FR-25 Must「アカウントを作成し」）。デザインに従うなら新しい世帯を画面から作れなくなる — 描き漏れか、外す意図かを確かめる | `アカウントを作る` は残し、見た目はデザインに合わせて整える（B-68）。作成は別の画面が持つ（B-73 / ADR-081）— ログインの `アカウントを作る` は作成画面へ移る操作で、作成画面（デザインに無い）はログインの画面と同じ見た目で `アカウントを作る` の見出し・2欄・`アカウントを作る` / `ログイン画面へ戻る` を置く |
