# 画面デザイン依頼プロンプト

**このリポジトリを知らないデザイン担当（Claude Design を含む）に渡すための依頼文**を置く。
各ファイルは、区切り線から下を**全文コピーして貼るだけで完結する**ように書いてある。

| ファイル | 対象 |
| --- | --- |
| `web.md` | レスポンシブ Web（PWA）。**MVP のスコープはこちら**（要件 3.2） |
| `mobile.md` | iOS / Android のネイティブアプリ（タブレット含む）。**MVP スコープ外の先行検討**（ADR-003） |

## 2本の関係

構造・状態・用語・禁止語・データの形は**同一**である。異なるのは次の3点だけ。

| | `web.md` | `mobile.md` |
| --- | --- | --- |
| 出力先の違い | 幅（〜480 / タブレット / デスクトップ）、PWA の standalone 起動、iOS の「ホーム画面に追加」案内 | iOS / Android の慣習、システムの戻る、セーフエリア、Dynamic Type、タブレットの2ペイン、アプリアイコン |
| やらないことの補足 | — | バーコード・OCR・カメラ、ウィジェット、ローカル DB による同期を**明示的に禁じている**（ネイティブだと思いつきやすいため） |
| 生成操作の扱い | 予告つきのブロック | 同左 ＋ **引っ張って更新に割り当てない** |

## 直すときの順序

**このファイル群は二次資料である。** 仕様を変えるときは、まず出所を直す。

1. `docs/requirements.md`（何を作るか）
2. `docs/domain-model.md`（用語・不変条件・確定事項）
3. `docs/screen-design.md`（画面の構造・状態・優先順位）
4. **そのうえで** `web.md` / `mobile.md` を追従させる

とくに**用語表と禁止語**、**画面の状態 S-1〜S-7**、**確定事項 C-3 / C-6 / C-8 / C-10 / C-12 / C-15 / C-16** は、
依頼文の中に「変えてはいけないもの」として埋め込んである。出所を変えたのに依頼文が古いままだと、**デザインが先に間違う。**
