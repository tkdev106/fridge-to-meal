# マイグレーション

`stock_items` などの表と RLS ポリシーを置く。**Supabase CLI はまだ依存に入っていない**ため、
現状は Supabase の SQL エディタに貼って適用する。CLI の導入と CI での適用は B-07b で決める
（実 Supabase への接続情報の置き場を決める周）。

## 決めごと

- ファイル名は `<YYYYMMDDHHmmss>_<動詞_対象>.sql`。**時刻は書いた時点の UTC。** 桁を揃えることで
  辞書順がそのまま適用順になる
- **1タスク1ファイル。適用済みのファイルは書き換えない。** 直すときは新しいファイルを足す
- **表の作成と RLS の有効化・ポリシーを同じファイルに置く。** 分けると、片方だけ適用された状態
  ＝**RLS の無い表が実在する窓**ができる
- **`service_role` で適用しない前提の内容にする。** 権限は `authenticated` にだけ与える（ADR-020 / NFR-09）

## RLS を書くときに落とさないこと

| 操作 | `using` | `with check` |
| --- | --- | --- |
| `select` | 要る | — |
| `insert` | **存在しない** | **要る** |
| `update` | 要る | 要る |
| `delete` | 要る | — |

**`insert` の `with check` を落とすと、他世帯の行を作れてしまう。** 作った本人には `select`
ポリシーで見えないため、画面上は何も起きていないように見え、**気づけない。**

**RLS は効いていないことに気づけない。** ポリシーを1行消してもアプリは正常に動き続ける。
実 Supabase に対する回帰テストは B-07b で置く。
