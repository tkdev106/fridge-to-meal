# navigation

**ここは画面ではない。** `features/` が画面の置き場であるのに対し、ここは画面を**並べる器**である。
下タブ（`docs/screen-design.md` 2.1）は献立・在庫・履歴という3つのコンテキストの画面を横に並べる
もので、**どれか1つの `features/` には置けない** — `features/pantry/` に置けば、在庫が献立と履歴を
抱える形になる。`server/` と `session/` を `features/` の外に出したのと同じ置き方である
（`server/README.md` / `session/README.md`）。

**層を1つ増やしたのではない。** `docs/adr.md` A章 の表は `apps/web/` をまとめてプレゼンテーション層に
対応づけ、**その表以外の対応を作らないこと**と定めている。ここもその内側である。

| ファイル | 役割 |
| --- | --- |
| `Tabs.ts` | タブの識別子（`TabId`）・並び（`TAB_ORDER`）・既定（`DEFAULT_TAB`）。**文言を持たない** |
| `TabbedScreen.tsx` | 帯（SP の下タブ・PC のサイドナビ。ロゴ・タブ3つ・帯の「設定」）と、選んだタブの中身または設定の出し分け。**日本語のラベルとタブのアイコンの対応はここだけ** |
| `TabbedScreen.module.css` | SP / PC の並びと、選んでいる / いないタブの見た目（`.tab` / `.tabSelected`）。**見た目の値はここだけ** |
| `ScreenHeader.tsx` | 見出しの行（`h1` の題と、その後ろの歯車 `aria-label="設定"`）。献立・在庫（一覧）・履歴の3つの一覧の先頭に置かれる（B-60 設計 6章 規則12〜14） |
| `ScreenHeader.module.css` | 見出しの行の見た目。余白は SP `16px 16px 24px`・PC `40px 0 32px`、歯車の押せる大きさは 48px で、**PC では歯車を `display: none` にする**（PC の入口はサイドナビの下端の「設定」） |

## ここで守ること

- **器は中身が何かを知らない。** 3つの中身は `ReactNode` で受け取るだけで、在庫の口
  （`listStockItems` ほか）もセッションも持たない。組み立てるのは門（`App.tsx`）である。
  器が継ぎ目を持つと、タブが増えるたびに器がそれを知ることになる
- **役割（ARIA）を3つ使う**（B-38 設計 5章）。帯は `role="tablist"`、各タブは `role="tab"` と
  `aria-selected`、中身は `role="tabpanel"`。文言が未確定である以上（`docs/screen-design.md` 論点3）
  タブを名前で引けず、**選んでいるタブを色だけでなく読み取れる形で示す**（NFR-17 の構え。
  同条の射程は期限の警告であり、タブの選択状態は入っていない）標準の手段が
  これである
- **帯は中身より後ろに描く**（NFR-14。片手操作で親指が届く画面の下端）。jsdom はレイアウトを
  持たないため、この規則は**文書順**として読む。**下端への固定は CSS が担う**（設計 B-59 6章
  規則10）— 文書順は「中身 → 帯」のまま変えず、帯を `position: fixed` で下端に重ね、中身の欄は
  帯の高さぶん（下端の安全域を含む）の余白を下に取って末尾を隠さない。下端への固定と
  この余白は SP のときだけである（B-60）
- **幅 1024px 以上（PC）では帯を左の幅 240px のサイドナビにする**（B-60 設計 6章 規則1〜6）。
  切り替えは CSS のメディアクエリだけで行い、**JS で幅を読まない**（`matchMedia` を使わない）。
  タブは1組だけで、SP の下タブと PC のサイドナビは同じ `tablist` を CSS で並べ替えたもの。
  PC で帯を左に置くのは外枠のグリッドであり、**DOM の順（中身 → 帯）は変えない**。PC では
  下端への固定と中身の欄の下余白を外し、サイドナビは画面の高さいっぱいに留まる。ロゴと帯の
  「設定」は SP で `display: none` にする（DOM には常にある）
- **設定は4つ目の行き先である**（B-60 規則7〜11）。帯の「設定」は `tablist` の外・`<nav>` の中に
  置く。`settings` が渡されている間は中身の欄にタブの中身の代わりに設定を描き、どのタブも
  選ばず（中身の欄は `tabpanel` にせず、`aria-controls` も付けない）、帯の「設定」が
  `aria-current="page"` を持つ。**開いているかを持つのは門**であり、タブが押されたら門が設定を
  閉じてそのタブを出す。開閉で選んでいるタブも開いている献立も変えない
- **`ScreenHeader` は `features/` から import してよい唯一の `navigation/` の部品である**（B-60 規則14。
  `icons/` と同じ「どの画面からも引く部品」）。器（`TabbedScreen`）と `Tabs.ts` は門だけが引く。
  逆向きは無い — **`navigation/` は `features/` を import しない**。`h1` には題の文字だけを入れ、
  歯車は文書順でその後ろに置く。設定を開いているかは持たず、押下を口で渡すだけである（ADR-066）
- **選んだタブの中身だけを描く。** 残る2つは `hidden` で隠すのでもなく、木に置かない
- **見た目の値は `TabbedScreen.module.css` にだけ置く**（B-41 設計 6章 規則6 / ADR-055 決定1）。
  `.tsx` に太さも色も直に書かず、各タブに `.tab`、選んでいるタブにはそれに加えて `.tabSelected`
  を当てるだけにする — 配色や寸法を詰める周が、ここ1か所を見れば足りる形にしておく。色と
  文字の大きさは `src/global.css` の `:root` のトークンから `var(--…)` で引く（ADR-055 決定2）。
  **トークンに無い寸法**（間 4px・線の 2px・内側 16px など。`docs/design/README.md`「トークン」は
  余白と線幅を持たない）**は原本の値を module に直に書く** — その部品にしか現れない値を
  `:root` に上げても引く側が1つしか無い。
  **単体テストが見るのは「選択で当たる class が違う」ことまでで、値は見ない**（ADR-055 決定3）。
  B-41 の置き場だったインラインの `style`（ADR-054）は置き換え済みである
- **選んでいるタブを色で区別しない**（同 規則3。NFR-16 / NFR-17 の構え）。文字色も背景色も
  選択で変えず、手がかりは**文字の太さ**と**線**（SP は上辺、PC は左辺。B-60 規則3）で出す。線の有無で
  帯の高さを動かさない — 線は帯の上の境界に重ねて描くので、有無で帯の高さも中身の位置も
  動かない（NFR-14）。色を足す周は WCAG 2.1 AA を確かめてから足し、**そのときも太さと線の
  手がかりを消さない**
- **タブのアイコンは飾りである**（`icons/README.md`）。タブの名前はラベルの文字だけが持つ
- **選んでいるタブは web の記憶の中だけに持つ。** URL にも `localStorage` にも書かない
  （**ルーティングの依存パッケージを足さない**。`CLAUDE.md`）。再読み込みは既定のタブに戻り、
  サインアウトを挟んでも戻る。**持つのは器ではなく門である**（ADR-066 決定2 / 結果1。B-38 設計
  6章 規則8 はここで置き換わった）— 器は `selectedTab` / `onSelectTab` を受け取るだけで、
  **サインアウトを挟んだ回に既定へ戻すのは門の効果**である（門は signedOut の間も生き続けるため、
  器の mount/unmount には頼れない）。**端末の「戻る」も URL を変えずに受ける** — 受けるのは
  `backNavigation/` で、印つきの項目を履歴に積むだけで URL もハッシュも書かない（ADR-084 / B-75）
- **既定は献立タブである**（2026-09-24 にユーザーが決定。ADR-064 / 要件 第7章 /
  `docs/screen-design.md` 2.2）。**B-49a で `DEFAULT_TAB` を `'meals'` に反転させた** — 献立タブが
  保存済みの提案を出すようになり（B-58 / ADR-065）、仮置きが起動画面になる心配が消えたため
- **中身のまだ無いタブも帯から消さず、無効化しない**（feature flag を置かない。
  `CLAUDE.md` / `docs/workflow.md` 1章）
- **`@supabase/*` を1つも import しない**（`apps/web/src/session/` だけの特権。ADR-046 決定3）。
  `apps/api` の中身も import しない
