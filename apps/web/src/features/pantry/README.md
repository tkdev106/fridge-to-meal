# features/pantry

在庫コンテキストに対応する画面。`docs/screen-design.md` の第5章（在庫タブ）と
第6章（食材の登録・編集）がここに来る。

**一覧・登録・編集の出し分けを持つのは `PantryTab.tsx` である**（B-39 / B-55）。在庫タブの中身は
**一覧の側（見出しの行と `PantryList`）を常に木に置き**、登録（`StockItemForm`）・編集
（`StockItemEditForm`）は開いている間だけその後ろにパネルとして置く（B-65b）。パネルの間は一覧の側を
`inert` にし、SP では CSS で隠して入れ替わりに見せ、PC（幅 1024px 以上）では右から幅 440px の
パネルとして並べる（ADR-076。幅を JS で読まない）。閉じたら焦点を開いた操作（`食材を追加` / その行の
`…`）へ戻す。いまどれを出しているかの状態はここにある — 器（`navigation/TabbedScreen.tsx`）にも門（`App.tsx`）にも
持たせない。門が一覧を取り直しても開いている登録・編集の画面は閉じず、別のタブを挟むと器が中身を
外すので閉じる。

**編集の画面は一覧の行から受け取った在庫品1件を抱える**（B-55 設計 規則17）— 識別子から一覧を
引き直さないのは、門が取り直した回に対象が入れ替わったり消えたりするためである。編集できるのは
**分量と期限だけ**で（FR-05）、名称は出すが変えられない。行のタップで開き（判断は `SwipeGesture.ts`
の `isTap`。なぞりとは同時に起きない）、**通った回だけ閉じて門が一覧を取り直す。**
**`update.notFound` は削除と読み分ける** — 「すでに消えている」と読み流さず案内を出し、画面も
閉じない（ADR-050 結果5。利用者は書いた内容を持っている）。断りの `rule` から案内を選ぶ表は
`UpdateFailureNotice.ts`（ADR-032 決定3）。

**行の操作と削除は `PantryList.tsx` が配線する**。左へなぞると `削除` が指に合わせて右から滑り込み、
押すと確認を挟まずに行を隠して `元に戻す` の帯を5秒出し、過ぎたら送る（取り消せる間は送らない）。
行末の `…`（全行の木に置き、見せるのは PC の幅だけ）を開くと `編集` / `削除` が出て、その `削除` は
確認（`StockItemDeleteConfirmation.tsx`。`role="dialog"` の自前で、最初の焦点は `やめる`）を開き、
**確認の `削除` を押したときに送る。** どの出来事でどの状態へ移るかは
`RowOperations.ts` の純粋関数が持つ。確認は**開いた時点の在庫品1件を抱え**、門が取り直しても
その在庫品で文を出し、その識別子で送る。結末の読みは削除の今のまま（`DeleteFailureNotice.ts` /
ADR-050）。
見た目は B-64 で入った（見出しの行・帯・行・暗幕と確認。値は `*.module.css`）。確認中は一覧を `inert` にする。幅 1024px（B-60 / ADR-076）未満の SP では確認を下から出る面にし、`…` は出さない（SP の削除は、行をなぞって現れる `削除` と編集の画面の `削除`）。PC では確認を中央に置き、`…` を行末の列に見せる。
